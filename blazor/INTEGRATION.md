# Hosting, callbacks and data

Use an interactive WebAssembly or Interactive Server render mode. Static SSR renders only a host/loading fragment; initialize browser resources after `Ready`. Assets resolve relative to the app base URI under `_content/ReactiveWeb.Blazor/`. Keep browser sessions per app/circuit, never as shared cross-user Server singletons.

Ordinary `ReactiveValue` and command-button content uses Razor fragments directly. For optional native DOM templates, register `builder.Services.AddReactiveWebBlazor()` and `builder.RootComponents.RegisterReactiveWebBlazor()` on WASM. On Server use `AddRazorComponents().AddInteractiveServerComponents(options => options.RootComponents.RegisterReactiveWebBlazor())`. Define a uniquely identified `BrowserTemplate<TItem>` and pass `BrowserFunction.RazorTemplate(id)` to a native factory. Independent roots support nested components, callbacks and shadow-DOM input binding, but do not automatically inherit outer cascading values. Declare needed `CascadingValue` components inside templates and store durable state outside recreated roots.

`BrowserModule` exposes constructor/invoke/call/get/set/event operations with native object identity. Use `InvokeReferenceAsync`, `CallReferenceAsync`, `GetReferenceAsync` for returned functions, and `CallFunctionAsync` or pass the handle into native pipelines. Synchronous selectors and comparers must be browser functions. `BrowserFunction.DotNet` is asynchronous and valid only for promise-compatible native APIs. Canceling an interop wait does not terminate arbitrary synchronous native computation or independent server-side work.

Complete DTO results use `CallJsonAsync`, `InvokeJsonAsync`, `GetJsonAsync`; binary results use their byte equivalents. The default explicit stream limit is 64 MiB. `SubscribeJsonAsync` is for full DTO notifications; `SubscribeAsync` is a bounded diagnostic snapshot of live native graphs. Batches preserve call order but are not atomic. Use `BrowserValue.Literal` for application arguments in generic interop so `$fn` keys cannot become callbacks; never accept untrusted module URLs as executable callbacks.

Dispose subscriptions, owned models/commands and modules asynchronously. Dispose borrowed JS handles without destroying their native owners. `ReleaseAsync` is for native resources you own. JSON values are copies. A canceled browser command cannot forcibly stop an arbitrary .NET task on the Server.

Source builds need recursive submodule initialization, npm ci/build and `node blazor/build.mjs`; NuGet consumers need neither Node nor Dockyard. CI restores produced nupkg consumers for net8.0/net10.0 and tests WebAssembly/Server at non-root paths, native commands and reactive values, full streams, Razor callbacks and remounting in Chromium. Physical GPU, hybrid WebViews and all browsers are not qualified.

NuGet versions are independent of npm in `Version.props`. Version-changing main merges publish after validation using `NUGET_API_KEY` (`NUGET_TOKEN`/`NUGET_KEY` aliases), reject conflicting immutable versions, verify public package payloads and create `blazor-v*` releases with symbols, runnable samples and checksums.
